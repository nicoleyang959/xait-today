# 小红书与抖音 AI 热点采集方案

更新时间：2026-09-01

## 目标

从小红书和抖音的公开可见页面中发现近 30 天高互动 AI 内容，为每日资讯简报提供选题线索。

这套方法只做趋势发现，不把平台热度当作事实证明。产品发布、融资、安全、政策和研究结论仍应回到企业官网、官方账号、论文或权威媒体核验。

## 公开来源与访问边界

### 小红书

- 使用正常登录后的只读搜索能力获取候选内容。
- 只记录页面公开显示的标题、作者、发布时间、互动量和原始链接。
- 不导出 Cookie、令牌、密码、浏览器存储或登录文件。
- 登录失效、验证码或风控出现时停止采集，由用户自行恢复登录。

### 抖音

- 使用正常登录后的浏览器进行只读关键词搜索。
- 只记录页面公开显示的作品信息与互动量。
- 不发布、不评论、不点赞、不收藏，也不批量下载视频素材。
- 不调用未向当前开发者身份开放的接口，不尝试绕过验证码或平台限制。

## 候选范围

- 主题：AI、人工智能、大模型、AI Agent、AI 工具、AI 产品等。
- 时间：以采集时刻向前 30 天为上限。
- 候选量：先加载足够候选，再进行时间过滤、去重与排序。
- 去重：优先使用内容 ID；无法取得 ID 时使用规范化来源链接。
- 输出：小红书和抖音各自最多保留 Top 10。

## 排序原则

两个平台的互动机制不同，因此只做平台内部排序，不把小红书和抖音的原始数值直接比较。

平台内热度可以综合三个信号：

```text
热度分 = 互动百分位 × 55 + 新鲜度 × 30 + 资讯相关度 × 15
```

- **互动百分位**：在同平台、同批候选中计算。
- **新鲜度**：发布时间越近权重越高，超过 30 天直接排除。
- **资讯相关度**：模型更新、产品发布、研究突破和行业事件高于纯观点或营销内容。

互动数据会持续变化，快照只代表采集时刻。对外展示时应同时保留采集时间和来源链接。

## 统一字段

```json
{
  "platform": "xiaohongshu | douyin",
  "id": "来源内容 ID",
  "title": "页面公开显示的标题",
  "author": "页面公开显示的作者名",
  "published": "可核验的发布时间",
  "engagement": 28000,
  "engagementLabel": "2.8万赞",
  "topic": "AI 工具",
  "url": "https://来源原始链接",
  "collectedAt": "2026-09-01T09:00:00+08:00"
}
```

最低必需字段为 `platform`、`title`、`author`、`published`、`engagement`、`url` 和 `collectedAt`。无法可靠判断的字段保留为空，不用猜测值补齐。

## 处理流程

1. 分别搜索一组固定 AI 关键词，加载足够候选。
2. 读取页面公开字段，不访问账号后台或浏览器隐私数据。
3. 过滤超过 30 天、无法识别时间或明显偏离 AI 主题的内容。
4. 按内容 ID 或规范化链接去重。
5. 在每个平台内部计算排序信号，各取 Top 10。
6. 写入带日期的 JSON 快照，并记录采集时间与来源状态。
7. 页面生成前校验字段结构、URL 协议、日期范围和重复项。

## 失败与降级

- 来源暂时不可用时沿用最近一次成功快照，并明确标记采集日期和陈旧天数。
- 登录失效、验证码或 CAPTCHA 出现时停止对应来源，不尝试自动绕过。
- 页面字段结构变化时停止写入新结果，避免把播放时长等字段误识别为互动量。
- 某个平台没有足够合格结果时按实际数量展示，不用低质量内容补满 Top 10。
- 原始链接失效时保留快照记录并标记不可访问，不生成替代来源结论。

## 质量检查

- 所有内容都在近 30 天范围内。
- 同一平台内没有重复内容 ID 或重复规范化链接。
- 每个平台不超过 10 条，并按平台内排序信号降序排列。
- URL 使用公开的 HTTP 或 HTTPS 地址。
- 作者名只使用来源页面公开显示名。
- 快照中没有 Cookie、令牌、密码、手机号、验证码、浏览器存储或本机文件路径。

## 公开仓库边界

公开仓库只包含：

- 脱敏后的历史 JSON 快照；
- 本方法说明；
- 使用快照生成的静态展示页面。

公开仓库不包含：

- 自动刷新脚本和个人登录态配置；
- Cookie、令牌、密码或浏览器存储；
- 数据库、翻译缓存、失败截图或原始抓取结果；
- 平台正文、图片、音频或视频素材。
